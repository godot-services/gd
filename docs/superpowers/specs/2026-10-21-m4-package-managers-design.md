# M4 Package Managers — Design

Status: draft · Date: 2026-10-21 · Refs: gd#42 · Builds on: [M4 release builds](2026-10-21-m4-release-builds-design.md), [ADRs](../../adr/README.md)

## Goal

Every stable release of `gd` is published automatically to:

- **Homebrew** (macOS and Linux): `brew install godot-services/tap/gd`
- **Scoop** (Windows): `scoop bucket add godot-services https://github.com/godot-services/scoop-bucket`, then `scoop install gd`

deb/rpm, winget, AUR and Nix are not part of this change; they move to a
follow-up issue.

## Context

- gd#41 (PR gd#73) builds the release archives with GoReleaser v2.18.3 on `v*`
  tags. Homebrew and Scoop consume those archives; GoReleaser writes the cask
  and manifest from the same config.
- GoReleaser v2.10+ generates Homebrew **casks** (`homebrew_casks`); formulas
  (`brews`) are deprecated. Its cask template has macOS and Linux sections, so
  one cask serves Homebrew on both.
- The binaries are not notarized (ADR 0021). Homebrew quarantines cask
  downloads on macOS, so without a hook Gatekeeper reports the binary as
  "damaged". GoReleaser documents a post-install hook that removes the
  quarantine attribute.
- `godot-services/homebrew-tap` and `godot-services/scoop-bucket` exist, are
  public and **empty** (no commit, REST `default_branch` is `main`). The
  contents API answers "This repository is empty" for them.
- The secret `TAP_GITHUB_TOKEN` exists in `godot-services/gd`: a fine-grained
  PAT with "Contents: read and write" on the two repositories only.
  `GITHUB_TOKEN` cannot write to other repositories.

## Decisions

| Question | Decision | ADR |
| --- | --- | --- |
| Managers first | Homebrew tap (cask) and Scoop bucket; deb/rpm, winget, AUR, Nix later | 0023 |
| Who maintains | GoReleaser writes the cask/manifest on every stable release; nobody edits them by hand | 0023 |
| Credentials | fine-grained PAT as `TAP_GITHUB_TOKEN`, scoped to the two repos | 0023 |
| Prereleases | not published (`skip_upload: auto`) | 0023 |
| macOS quarantine | cask post-install hook runs `xattr -dr com.apple.quarantine` on the binary | 0023 |

Rejected: a GitHub App instead of the PAT (more setup for two repos; can be
switched later without changing the config shape); winget now (PRs to
`microsoft/winget-pkgs` need a fork and a manual review of the first
submission); deb/rpm now (not chosen for the first step).

## Design

### `.goreleaser.yaml`

```yaml
homebrew_casks:
  - name: gd
    binaries: [gd]
    homepage: https://github.com/godot-services/gd
    description: Package manager for Godot projects
    license: MIT
    skip_upload: auto
    repository:
      owner: godot-services
      name: homebrew-tap
      token: "{{ .Env.TAP_GITHUB_TOKEN }}"
    hooks:
      post:
        install: |
          if OS.mac?
            system_command "/usr/bin/xattr", args: ["-dr", "com.apple.quarantine", "#{staged_path}/gd"]
          end

scoops:
  - name: gd
    homepage: https://github.com/godot-services/gd
    description: Package manager for Godot projects
    license: MIT
    skip_upload: auto
    directory: bucket
    repository:
      owner: godot-services
      name: scoop-bucket
      token: "{{ .Env.TAP_GITHUB_TOKEN }}"
```

The cask lands in `Casks/gd.rb` (GoReleaser default), the manifest in
`bucket/gd.json` (Scoop's convention for buckets). Commit author is GoReleaser's
default bot.

### `.github/workflows/release.yml`

The GoReleaser step gets `TAP_GITHUB_TOKEN: ${{ secrets.TAP_GITHUB_TOKEN }}`
in its `env`. Nothing else changes. The snapshot job in `test.yml` does not get
the secret (PRs from forks would not have it anyway); a snapshot never
publishes, it only writes `dist/homebrew/` and `dist/scoop/`.

### Seeding the two repositories

GoReleaser's `CreateFile` reads the default branch and the existing file
before writing; against an empty repository that path is untested by us. Each
repository therefore gets one initial commit on `main` with a short
`README.md` (what it is, the install command, "generated by the gd release
workflow, do not edit by hand") and `LICENSE` (MIT, as in gd). This is a push
to repositories outside `gd` and needs the user's OK; it is done from the
local clones `/Users/naxmefy/work/godot-services/homebrew-tap` and
`/Users/naxmefy/work/godot-services/scoop-bucket`.

## Error handling

- Token missing, expired or without access: the GitHub release and its assets
  are already published when the cask/manifest push fails; the job is red.
  After fixing the token, re-running the job is safe (`keep-existing`,
  `replace_existing_artifacts`; the cask/manifest commit simply updates the
  file). The release title has to be edited again (ADR 0020).
- Prerelease tags (`v0.5.0-rc.1`): `skip_upload: auto` skips the cask and
  manifest when the tag has a prerelease part, so Homebrew and Scoop users stay
  on stable versions. `release.prerelease: auto` is added as well, so such a
  GitHub release is marked as a prerelease and not as "latest".

## Testing

- `goreleaser check` validates the config.
- `goreleaser release --snapshot --clean` (without `TAP_GITHUB_TOKEN` set)
  succeeds and writes `dist/homebrew/Casks/gd.rb` and `dist/scoop/gd.json`.
  The cask has `on_macos`/`on_linux` sections with arm64 and amd64 URLs
  pointing to `https://github.com/godot-services/gd/releases/download/v…/gd_…`,
  the SHA-256 values from `checksums.txt`, and the post-install hook; the Scoop
  manifest has `64bit` and `arm64` entries with the windows zips and their
  hashes.
- If Homebrew is available locally: `brew style` on the generated cask passes.
- `actionlint` on the workflows.
- The real push to tap and bucket only runs on the next stable tag; after it,
  `brew install godot-services/tap/gd && gd --version` and (on Windows)
  `scoop install gd` are the acceptance check.

## Out of scope

deb/rpm/apk packages and an apt/yum repository, winget, AUR, Nix, a GitHub App
token, signing the cask or manifest commits.
